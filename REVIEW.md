# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns static `{"status": "ok"}` without checking if MongoDB is alive. Does not satisfy contract requiring 503 when DB is unreachable. | Stop MongoDB service; `GET /health` still returns 200 instead of 503. | Added `client.admin.command("ping")` inside a `try/except` block, raising `HTTPException(503)` if ping fails. |
| 2 | `create_employee` (lines 78-85) | Race condition in employee creation. Check-then-insert (`find_one` then `insert_one`) allows duplicate `emp_code` records under concurrent requests. | Fire two concurrent `POST /employees` requests with identical `emp_code`; both can pass check or one throws unhandled 500. | Created unique index on `employees.emp_code` at startup and caught `DuplicateKeyError` to return 409. |
| 3 | `EmployeeIn` / `create_employee` (lines 53-60, 77) | Missing validation that `shift_start != shift_end`. Contract states shift start and end must differ. | Send `{"shift_start": "09:30", "shift_end": "09:30"}`; accepted with 201 instead of 422. | Added validation method checking `shift_start == shift_end` and raising 422 unprocessable entity. |
| 4 | `create_employee` (lines 81-84) | Stored `created_at` as naive local datetime `datetime.now()` and returned raw internal values. API contract requires integer epoch milliseconds. | Inspect response of `POST /employees`; `created_at` is datetime string/object rather than integer epoch milliseconds. | Stored UTC datetime `datetime.now(timezone.utc)` and formatted `created_at` to epoch milliseconds in serialized output. |
| 5 | `list_employees` (line 93) | Off-by-one pagination bug: `skip = page * page_size` skips the first page entirely (e.g. for page=1, it skips 20 items instead of 0). | Request `GET /employees?page=1&page_size=20`; returns empty list or skips the first 20 records. | Changed skip calculation to `(page - 1) * page_size`. |
| 6 | `list_employees` (line 94) | `total` counts the whole collection `count_documents({})` instead of reflecting the filtered department count. | Request `GET /employees?department=Engineering`; `total` returns 6 instead of the 2 engineering employees. | Changed count call to `count_documents(q)`. |
| 7 | `list_employees` (line 95) | Missing sort order. Contract requires items sorted by `emp_code` ascending. | Insert employees out of order; response order is undefined MongoDB insertion order. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 8 | `punch_in` (lines 100-105) | Check-then-insert race condition on `(emp_code, date)`. Simultaneous punch-ins both pass `find_one` check. | Fire two concurrent punch-in requests for same employee and date; both succeed with 201 or produce duplicate logs. | Created compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to reliably return 409. |
| 9 | `punch_in` (lines 101, 113) | Unhandled `KeyError` when employee does not exist. If `find_one` returns `None`, `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable`, yielding HTTP 500 instead of 404. | Send `POST /attendance/punch-in` with non-existent `emp_code: "EMP9999"`; returns 500 Internal Server Error. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in` (lines 102-103) | Attendance date derivation ignores overnight shifts (R1). Also uses naive `datetime.fromtimestamp` without UTC/IST awareness. | Punch in at 05:00 IST for a 22:00-06:00 overnight shift; record is assigned to current calendar day instead of previous shift start date. | Implemented `determine_attendance_date` with IST timezone and overnight shift boundary check (`time < shift_end`). |
| 11 | `compute_late_minutes` (lines 33-37) | Flawed late calculation. Uses naive `replace()`, does not floor minutes, does not enforce whole second truncation, and fails for overnight shifts. | Punch in at 09:40:01 for 09:30 shift; starter gives wrong late minutes or crashes across day boundaries. | Replaced with strict R2 calculation using floor of seconds elapsed after `shift_start_ist` when strictly > 600s. |
| 12 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which implements banker's rounding (round half to even) instead of decimal half-up required by R4 and R8. | Calculate work hours for seconds resulting in exact midpoint `.005`; built-in `round()` rounds to nearest even number. | Implemented `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 13 | `compute_overtime` (lines 44-47) | Does not apply the 30-minute minimum threshold (R3) and assumes shift end is on same calendar date (breaks overnight shifts). | Punch out with 15 minutes past shift end; starter awards 15 minutes overtime instead of 0 (threshold is >= 30). | Rewrote overtime logic to account for overnight shift dates and require `ot_minutes >= 30`, returning 0 otherwise. |
| 14 | `list_attendance` (lines 144-147) | In-memory full collection scan: loads all matching documents into memory via `list(db.attendance_logs.find(q))` and sorts in Python. Catastrophic for 100k documents. | Measure query time and memory footprint on 100,000 records; causes high latency and memory exhaustion. | Pushed sorting and pagination into MongoDB engine using `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`. |
| 15 | `list_attendance` & `punch_in` (lines 119, 149) | Injects internal `id: str(_id)` into attendance objects. OpenAPI specification dictates `_id` and `id` must never appear in responses. | Validate response against OpenAPI schema `AttendanceRecord`; fails validation due to unexpected `id` field. | Removed `id` injection and stripped `_id` in `serialize_doc`. |
| 16 | `list_attendance` (lines 127-128) | Missing validation for date range ordering. If `date_from > date_to`, query runs with impossible range instead of returning 422. | Send `GET /attendance?date_from=2026-07-10&date_to=2026-07-01`; returns 200 with empty list instead of 422. | Added validation raising `HTTPException(422)` when `date_from > date_to`. |

## What was examined and decided was NOT a defect

1. **`IST = timezone(timedelta(hours=5, minutes=30))`**: Defining IST as a fixed offset of +05:30 is correct because Indian Standard Time does not observe Daylight Saving Time.
2. **`load_dotenv()` at top of file**: Retained because standard practice allows reading local development credentials while `os.getenv` still allows injected environment variables to take priority.
3. **Pydantic model naming (`EmployeeIn`, `PunchInIn`)**: While renamed to match OpenAPI schemas (`EmployeeCreate`, `PunchInRequest`, `PunchOutRequest`, `RegularizeRequest`) for clarity, using separate request models in FastAPI is correct design.
